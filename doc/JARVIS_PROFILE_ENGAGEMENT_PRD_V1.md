# JARVIS 用户个性化与成就体系 PRD V1.0

## 1. 背景

JARVIS 当前用户资料仅支持昵称，账户菜单无法承载头像、签名、联系方式、动态公开权限，也没有可见的长期使用反馈。为了让用户形成持续研究习惯，需要完整的个人主页和轻量成就体系。

## 2. 产品目标

1. 用户可维护头像、签名、联系方式和资料公开范围。
2. 用户可以查看自己的公开动态和成就。
3. 用“研究行为”而非单纯游戏化点击来设计勋章，避免金融工具变成签到游戏。
4. 连续登录、研究任务、自动化任务、社区贡献等长期行为形成可见进度。

## 3. 个人资料需求

### FR-PRO-01 基础资料

- 昵称：1–60 字。
- 头像：支持 HTTPS 图片 URL，空值使用首字母占位头像。
- 个人签名：最多 160 字。
- 联系方式：最多 200 字，由用户自行填写。

### FR-PRO-02 隐私设置

三个独立开关：

- `profilePublic`：其他用户能否查看头像与签名。
- `contactPublic`：其他用户能否查看联系方式。
- `activityPublic`：其他用户能否查看动态与成就。

当前用户查看自己的资料时不受上述开关限制。

### FR-PRO-03 个人主页

个人中心展示：

- 头像、昵称、签名；
- 资料完整度；
- 连续登录天数；
- 成就勋章；
- 最近动态；
- 隐私开关与编辑表单。

## 4. 成就体系

### 登录类

- `FIRST_LOGIN`：完成登录。
- `STREAK_3`：连续登录 3 天。
- `STREAK_7`：连续登录 7 天。

### 研究类

- `FIRST_RESEARCH`：完成 1 个研究任务。
- `RESEARCH_5`：完成 5 个研究任务。

### 自动化类

- `FIRST_AUTOMATION`：创建至少 1 个定时任务。
- `TASK_ACHIEVER_5`：自动化任务成功执行 5 次。

### 社交类

- `FIRST_POST`：发布首条社区动态。
- `FIRST_GROUP`：加入或创建首个研究小组。
- `FIRST_MESSAGE`：发送首条站内私信。

### 资料类

- `PROFILE_COMPLETE`：昵称、头像、签名和联系方式均完成。

## 5. 连续登录计算

复用已有 `audit_event` 中 `USER_LOGIN / USER_GITHUB_LOGIN / USER_GITHUB_REGISTER`，按自然日去重后从今天向前计算连续天数。无需为了签到再建立一套登录流水。

## 6. 成就解锁原则

1. 成就规则由服务端定义，客户端只负责展示。
2. 成就一旦解锁即持久化 `unlocked_at`，后续条件变化不会撤销。
3. 成就接口每次读取时会重新评估未解锁规则，保证已有用户也能补发历史成就。
4. 解锁事件写入 `user_activity`，形成个人动态。

## 7. 验收标准

1. 用户可以编辑头像 URL、签名、联系方式与三个隐私开关。
2. 其他用户资料严格遵守隐私开关。
3. 连续登录天数可根据审计事件正确计算。
4. 研究任务、定时任务、社区行为可触发对应勋章。
5. 成就一旦解锁不会重复创建。
6. 个人中心可展示成就和近期动态。
