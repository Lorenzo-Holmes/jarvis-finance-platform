# 金融 Agent 工作流需求

## 1. 背景与范围

当前 AI 中心以单轮对话和若干独立分析接口为主，用户只能看到最终回答，无法知道系统是否制定了研究计划、调用了哪些金融工具、工具返回了什么证据，也无法在失败时停止或恢复运行。

本阶段将 JARVIS 升级为可观察的金融 Agent 工作流：用户提交研究目标后，系统创建一次 Agent Run，按计划调用只读金融工具，通过 SSE 实时推送执行事件，并在完成后生成带证据关联的研究结论。

本阶段不允许 Agent 自动下单、修改订单或执行其他资金影响操作。

## 2. 用户故事

- 作为投研人员，我希望看到 Agent 当前正在执行的计划和步骤，从而理解研究进度。
- 作为投研人员，我希望查看工具调用的名称、输入摘要、输出摘要、耗时和数据来源，从而判断结论是否可信。
- 作为投研人员，我希望 Agent 失败时看到明确原因，并能停止、重试或继续研究。
- 作为投研人员，我希望刷新页面后仍能查看已经完成的研究运行和执行轨迹。
- 作为平台管理员，我希望 Agent 运行复用现有登录、权限、配额和审计边界。

## 3. EARS 验收标准

1. 当用户提交研究问题时，系统应创建带唯一 `runId` 的 Agent Run，并先推送 `run_started` 和 `plan_created` 事件。
2. 当 Agent 调用金融工具时，系统应按顺序推送 `step_started`、`tool_call`、`tool_result` 和 `step_completed` 事件，并包含步骤状态与耗时。
3. 当工具调用失败时，系统应推送脱敏后的 `run_failed` 或步骤失败事件，说明可理解的错误原因，不泄露 API Key、Cookie、内部令牌或完整异常堆栈。
4. 当 Agent 正在执行时，AI 中心应显示可折叠的纵向执行轨迹，并实时更新运行中、成功、失败、取消状态。
5. 当用户点击停止时，系统应取消对应 Agent Run，停止后续工具调用，并将前端状态更新为 `cancelled`。
6. 当用户未登录、无功能权限或 AI 配额不足时，系统不得创建 Agent Run，并返回明确的认证、权限或配额错误。
7. 当 Agent 完成研究时，系统应推送 `run_completed`，并展示最终 Markdown 结论以及所引用的证据摘要。
8. 当用户重新打开研究任务或运行历史时，系统应能读取已完成或失败运行的摘要和事件轨迹。
11. 当浏览器与 Agent SSE 连接断开时，系统应保留 `runId`，允许从 PostgreSQL 重放已落库事件；运行仍未结束时可重新订阅同一运行，不得创建第二次执行。
9. 系统不得将模型隐式思维链原文展示给用户；仅展示计划摘要、工具调用、结果摘要和可验证证据。
10. 系统不得通过 Agent 工作流自动创建、修改、取消真实交易或模拟交易订单。

## 4. 约束与非目标

- 保留现有 `/api/ai/chat` 和 `/api/ai/chat/stream` 兼容行为。
- Agent 只使用现有 Java 行情、研究、风险和新闻服务作为首批工具来源；工具白名单包括新闻、财报、行情、日 K、技术指标和风险检查。
- 工具输入和输出必须限制长度，必要时只展示摘要。
- Agent 事件使用 SSE 实时传输；历史记录通过普通 JSON API 查询。
- `agent_run` 与 `agent_event` 通过 Flyway 持久化到 PostgreSQL，事件按 `runId + sequence` 唯一排序。
- 不在本阶段引入多 Agent 协作、自动交易、后台批量投资决策或外部工具市场。
